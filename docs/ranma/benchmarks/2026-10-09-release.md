- Measured: 2026-10-08 and 2026-10-09
- Method: [method.md](method.md); the settings of these rows below.

Three models, each in the EXL3 conversion this fork publishes and in a general GGUF, on the Radeon AI PRO R9700 and on

## Settings

**Systems.** The RX 9070 XT rows are the same R9700 with the placement of a 16 GiB card
([method.md](method.md#machine)). The fork gives the expert cache an L1 (VRAM) budget of 20480 MiB on the R9700. On
the 9070 XT the budget is 3072 MiB for Qwen, 4096 MiB for DeepSeek and 5120 MiB for GLM. Upstream places the
routed experts with `-ncmoe`: 35 / 45 for Qwen, 33 / 41 for DeepSeek and 38 / 44 for GLM (R9700 / 9070 XT). Those are
the smallest values that keep the device weights under 29 GiB on the R9700 and under 13.5 GiB on the 9070 XT, computed
from the expert sizes per layer. Every 9070 XT row stays under 15 GiB of dedicated memory: the fork 8.3 to 12.8 GiB,
upstream 11.0 and 14.6 GiB.

**Host memory.** The host tier (L2) is the system memory minus 24 GB: `--expert-l2-mib` 106496 at 128 GB (92160 for
GLM, which leaves room for its larger non-expert part), 40960 at 64 GB and 8192 at 32 GB. The 64 and 32 GB rows also
take physical memory away from the machine ([method.md](method.md#host-memory-128-64-and-32-gb)). Each process starts
with the system memory minus 12 GiB available (52 and 20 GiB), so the page cache cannot hold the model file and the
file tier reads from the SSD, as on the smaller machine. The 128 GB rows run on the whole machine.

**`llama-bench` rows.** The command of [method.md](method.md#llama-bench-rows) with `-d 0` only. These rows have no
discarded warm-up pass, so PP512 at depth 0 is the first prompt of the process and varies by up to about 10 % from
process to process (Qwen EXL3 R9700: 1125 at 128 GB, 1189 at 64 GB and 1223 at 32 GB). TG128 is not affected. Every
fork row is warm: it starts from its own copy of the profile that a cold depth-0 run of the same model file wrote on
the R9700 with 128 GB, and runs with `--expert-prefill-swap`. The cold runs are not in the tables. The rows of one file
on the six systems share that profile.

**Detailed rows** (R9700, 128 GB, the EXL3 files): `llama-bench -d 0,8192,32768` in one process, cold and then warm from
a copy of that cold profile, with no warm-up pass. The server scenarios use the presets and the server row of
[method.md](method.md#server-rows) with MTP and `--spec-smart`, warm from a profile and a store that the warm-up preset
wrote in a separate process (as in [the EXL3 record](2026-10-05-exl3.md)). MTP for Qwen uses the draft
`mtp-Qwen3.8-Flash-Next-Q8_0.gguf` with `--expert-cache-draft on` and L1 20480. MTP for DeepSeek uses the draft
`DeepSeek-V4-Flash-MTP-3.93bpw.gguf` with `--expert-cache-draft off` and L1 16384. MTP for GLM uses the model's own NextN
head with L1 18944. All three use `GGML_CUDA_TOP_K_STABLE_TIES=1` and `ROCBLAS_USE_HIPBLASLT=0`.

Every process starts after the temperature gate of [method.md](method.md#rests). One GPU process runs at a time,
and each row is measured once.

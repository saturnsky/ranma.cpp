# MTP draft length: `--spec-smart` against the single-argument values

- Release: `ranma_20261001` (measured on a development build of its series, before `--spec-smart` became the default)
- Upstream base: `ed7ac35e1`
- Measured: 2026-10-01
- Method: [method.md](method.md); the settings of these rows below.

Measured on 2026-10-01 on the Radeon AI PRO R9700 with 128 GB of host memory, with one build of the series of
ranma_20261001 made before `--spec-smart` became the default of `draft-mtp` ([spec-smart.md](../spec-smart.md)); its rows
pass the values that are the defaults of ranma_20261001 (`--spec-draft-n-max 7`, half-life 250). Four methods per model and scenario:

- **no MTP**: `--spec-type none`;
- **MTP, single argument**: the values that the launchers of this machine used, tuned here for these two models:
  Qwen3.8-Flash-Next `--spec-draft-n-max 2 --spec-draft-p-min 0`, DeepSeek V4 Flash
  `--spec-draft-n-max 1 --spec-draft-p-min 0`;
- **smart, cold**: `--spec-smart` starting with an empty store (as a server without `--spec-smart-store`);
- **smart, warm**: the same, starting from a copy of the store that the cold row of the same scenario saved.

Scenarios: coding (12 requests), roleplay in English, Korean, Chinese and Japanese (17 requests each; the presets of
[method.md](method.md#server-rows)), and a mixed
scenario of 45 requests in 32 conversations (English roleplay 12, coding 9, Korean roleplay 12, English roleplay
12, in this order in one server process). Every row is a fresh server process after a 300 s rest, all 48 rows ran
the same build, greedy decoding with at most 384 tokens per reply, context 65536, one slot. Expert cache exclusive,
`--expert-l1-mib 20480`, unlimited host tier, prefill swap off, warm expert profile (the same seed profile for the
four methods of a scenario), joint cache on (`--expert-cache-draft on`), the MTP head on the GPU (`-ngld 999`):
`mtp-Qwen3.8-Flash-Next-shared-Q8_0.gguf` for Qwen3.8-Flash-Next UD-Q4_K_XL, the separate DeepSeek V4 Flash MTP
head GGUF for DeepSeek V4 Flash UD-IQ3_XXS.

The environment of every row also sets `GGML_CUDA_TOP_K_STABLE_TIES=1` (the stable tie selection of the radix top-k,
for selections that can be compared between runs) and `ROCBLAS_USE_HIPBLASLT=0`. The smart rows also pass, as options
of that build, the values that are fixed in ranma_20261001: `--spec-smart-lookahead-mix 0.5`,
`--spec-smart-conf-cap 16` ([fixed constants](../spec-smart.md#fixed-constants)) and `--spec-smart-cost-lcb 0`, the
setting without the cost bound that ranma_20261001 removed.

- Against no MTP, every MTP row is faster: the single argument by 19.7 to 29.5 % (Qwen) and 9.8 to 14.6 %
  (DeepSeek), smart by 17.2 to 23.9 % and 5.6 to 12.8 % cold.
- Against the single argument, smart is within a few percent. Qwen: cold -4.3 to +0.6 %, warm -1.9 to +2.6 %
  (faster than the single argument in five of six scenarios once warm). DeepSeek: coding is 1.0 % (cold) and 1.5 %
  (warm) faster and the mixed scenario 0.9 % (cold) and 0.6 % (warm) slower, but every roleplay scenario is 1.5 to
  3.8 % slower cold and 1.3 to 3.2 % slower warm; a warm store does not close that gap.
- The single-argument values are not general: they were chosen on this machine for these two models and this
  expert cache setting. Smart has no per-model values and reaches about the same throughput, which is why it is the
  default of `draft-mtp` in ranma_20261001; `--no-spec-smart` or the thresholds give the single-argument rule back.
- Replies (greedy): the methods give different replies, because the draft length changes the width of the
  verification batch and with it the kernels. The single-argument row of the Qwen mixed scenario gives the same
  replies (the same reply hash) as that row did on an earlier build of this series.

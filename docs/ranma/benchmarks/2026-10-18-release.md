# Release table: DeepSeek V4.1 Flash EXL3 with layer-major prefill

- Release: `ranma_20261018`
- Upstream base: `8f574b0ad`
- Measured: 2026-10-18
- Method: [method.md](method.md); the settings of these rows below.

One model, `DeepSeek-V4.1-Flash-EXL3-3.0bpw-h6` (EXL3 by Mia-AiLab) with its engram tables
`DeepSeek-V4.1-Flash-engram-MXFP8`, on the Radeon AI PRO R9700 with 128 GB and 192 GB of host memory. Server scenarios
(coding, Korean roleplay) and prompt processing at 512, 4096 and 32768 tokens. Layer-major prefill
([layer-mode.md](../layer-mode.md)) is on, and n-gram drafting (`--spec-type ngram-varlen`) is the only draft; there is
no draft model.

## At a glance

| system | decode, coding | decode, Korean roleplay | prompt 512 | prompt 4096 | prompt 32768 |
|---|---:|---:|---:|---:|---:|
| R9700, 128 GB | 22.85 t/s | 24.34 t/s | 82.0 t/s | 364.7 t/s | 662.3 t/s (49.5 s) |

Decode is the total of the evaluation preset (generated tokens over generation time). The four statistics of every
row, the draft acceptance, the prompt times and memory are in the sections below.

## Settings

**Machine.** The machine of [method.md](method.md#machine): 224 GB of DDR5-5600 in a flex-channel layout, whose
effective bandwidth is about that of DDR5-4900 (x0.875). Both systems are emulated on it by taking physical memory
away ([method.md](method.md#host-memory-128-64-and-32-gb)): every process starts with the emulated RAM minus 8 GiB
available, 120 GiB for 128 GB and 184 GiB for 192 GB. Where the process's memory lands in the faster or the slower
part of the flex-channel layout is not controlled.

**Server.** Every row runs:

```
llama-server -m DeepSeek-V4.1-Flash-EXL3-3.0bpw-h6-00001-of-00006.gguf -ngl 999 --fit off -fa on -ctk f16 -ctv f16 \
    -t 16 -tb 16 --poll 0 --poll-batch 0 --parallel 1 --ctx-size 65536 --jinja \
    --load-mode none --lazy-mode auto --ple-prefetch always --gpu-heartbeat-seconds 5 \
    --ctx-checkpoints 4 --cache-ram 0 --layer-mode on --spec-type ngram-varlen \
    --expert-cache-mode exclusive --expert-l1-mib auto --expert-l1-lru-pct 30 --fit-target 2048 \
    --expert-l2-mib <L2> --expert-profile-dir <profile>
```

with the engram tables next to the model, `GGML_CUDA_HOST_DIRECT=1` in the environment and no other switch. No batch
size is given: layer-major prefill picks its width (8192 on these rows). L2 is the emulated RAM minus 24 GiB:
106496 MiB at 128 GB and 172032 MiB at 192 GB. `--expert-l1-mib auto` with `--fit-target 2048` gave an L1 of
19533 MiB on both systems.

**Presets and sampling.** The coding and Korean roleplay presets of [method.md](method.md#server-rows). The warm-up
process replays the first 5 conversations of the warm-up preset from an empty profile directory; the evaluation process
starts from a copy of that profile and replays 10 conversations with every turn: 12 coding requests and 17 Korean
roleplay requests. Sampling is the model's recommended setting (temperature 1.0, top-p 0.95, top-k 0, min-p 0,
seed 1), with at most 10000 generated tokens per request. The replies are not fixed, so the rows generate different
amounts of text; the tables give the generated tokens.

**Prompt rows.** One process per system, a copy of the Korean roleplay warm-up profile, and prompts cut from real
roleplay and coding conversation logs to exactly 512, 4096 and 32768 tokens, no prompt caching. A discarded
32768-token prompt runs first ([method.md](method.md#prompt-rows)). Each length runs once.

Every process starts after the temperature gate of [method.md](method.md#rests). One GPU process runs at a time.

  of the earlier requests. The other rows kept the occupier resident throughout.

## Prompt processing

| system | 512 tokens | 4096 tokens | 32768 tokens | discarded first pass, 32768 tokens |
|---|---:|---:|---:|---:|
| R9700, 128 GB | 6.24 s, 82.0 t/s | 11.23 s, 364.7 t/s | 49.48 s, 662.3 t/s | 46.35 s, 706.9 t/s |
| R9700, 192 GB | 3.20 s, 159.9 t/s | 6.67 s, 614.5 t/s | 35.06 s, 934.5 t/s | 39.75 s, 824.4 t/s |

The time is the server's prompt evaluation time of the request, with exactly the requested number of tokens processed
and nothing reused from the cache.

**Where a 32768-token prompt spends its time.** Layer-major prefill takes the first 24572 tokens (three ubatches of
8192) in one call. It runs the first 20 layers layer by layer, reading each expert of a layer at most once; the last
20 layers only write their raw KV for these tokens (the exact tail prefill of DeepSeek V4.1,
[layer-mode.md](../layer-mode.md#the-logical-batch)). The remaining 8196 tokens, which end at the server's context
checkpoints, run as ordinary ubatches. From the server log (`RANMA_LAYER_EXEC_LOG=1`):

| system | layer-major part | of which non-expert graphs | of which experts | the remaining 8196 tokens |
|---|---:|---:|---:|---:|
| R9700, 128 GB | 31.4 s | 21.5 s | 9.8 s | 18.1 s |
| R9700, 192 GB | 24.5 s | 19.0 s | 5.4 s | 10.5 s |

With every expert read once per layer, the non-expert graphs (attention, the KV compressor and indexer,
hyper-connections, the engram rows and the raw KV of the tail layers) take most of the layer-major part. At 128 GB the
host tier leaves 77038 MiB of experts in the SSD tier (9859 MiB at 192 GB), which is the larger expert time of that
row.

## Against the ranma_20261013 rows

The DeepSeek V4.1 Flash rows of [the 2026-10-13 record](2026-10-13-release.md) run the same evaluation presets on the
same model, but this is not an A/B comparison: the settings differ in several ways at once.

| system | release | decode, coding | decode, Korean roleplay | prompt time, coding | prompt time, Korean roleplay |
|---|---|---:|---:|---:|---:|
| R9700, 128 GB | ranma_20261013 | 21.11 | 21.88 | 34.4 s | 142.0 s |
| | ranma_20261018 | 22.85 | 24.34 | 32.3 s | 58.4 s |
| R9700, 224 GB (2026-10-13) / 192 GB (2026-10-18) | ranma_20261013 | 23.66 | 23.89 | 21.3 s | 98.0 s |
| | ranma_20261018 | 25.32 | 26.62 | 23.4 s | 45.1 s |

What differs besides the release: n-gram drafting (the 2026-10-13 rows have no draft), sampling (greedy then,
temperature 1.0 now, so the replies and the conversation histories differ), layer-major prefill, `--ctx-size` 65536
instead of 32768, the warm-up of 5 conversations instead of 10, at 128 GB an L2 of 106496 instead of 92160 MiB and
120 instead of 116 GiB available at the start, and in the second pair a 192 GB emulation instead of the whole 224 GB
machine.

## Not measured

- The RX 9070 XT emulation (16 GB card), and DeepSeek V4.1 Flash with the DSpark draft model: the latest rows are in
  [the 2026-10-13 record](2026-10-13-release.md).
- The other models: layer mode turns off with an MTP context ([layer-mode.md](../layer-mode.md#supported-setups)),
  so the models that gain from MTP (Qwen3.8-Flash-Next, DeepSeek V4 Flash, GLM-5.3 Flash) were left out of this
  release table; their latest rows are in [the 2026-10-13 record](2026-10-13-release.md).
- Upstream: it cannot load the EXL3 files.
- Prompts longer than 32768 tokens.
